# Нативные репорты Astoria

## Что делает приложение

«Подготовить репорт» открывает локальный диагностический снимок, а не отправляет
данные разработчику. В предпросмотре виден полный JSON будущего содержимого,
ограничения и каждый включённый блок. История/заголовки добавляются отдельно;
согласие на чтение данных приложения не является согласием на экспорт.

Можно исключить блок. Вместе с ним исключаются зависимые комментарии и выводы;
старый предпросмотр больше нельзя сохранить. Смена БД/сессии/исходного владельца,
отзыв доступа и отмена прекращают не допущенную к сохранению операцию.

Снимок содержит ограниченные наблюдаемые факты, а не полный дамп БД или точный
исторический prompt. Отсутствие записи не доказывает её удаление. Авторский текст
помечен как личный комментарий, не как установленная причина ошибки. API-ключи,
токены, auth/vault/authority-поддеревья, внутренние квитанции и сырые транспортные
пакеты не включаются. Лимит канонического содержимого — 256 KiB.

После отдельного нажатия сохранения создаётся только шифрованный файл с нейтральным
именем `astoria-support-report.astreport`. Автоматической загрузки в Discord или
на сервер нет. Пользователь сам решает, прикладывать ли файл к своему обращению.
Отправка репорта не гарантирует, что данных достаточно для исправления ошибки.

На Android выбор места может создать пустой документ раньше передачи шифротекста.
Удаление такого документа после отмены — best effort. Уже начатый OS I/O нельзя
обещать отменить; возможный пустой/неполный файл не считается успешно сохранённым
репортом. Передавать стоит только файл после подтверждённого успешного сохранения.

## Криптография и получатель

Используется нативный libsodium через `sodium 4.0.3`: случайный ключ пакета,
XChaCha20-Poly1305 IETF для содержимого и `crypto_box_seal` для ключа пакета.
Полный ограниченный заголовок аутентифицируется. Декодер проверяет формат,
получателя, sealed key и AEAD до вывода содержимого. Plaintext ZIP/temp-файлы
не создаются. Файл и предпросмотр — разные вещи; ciphertext не является резервной
копией всей БД.

Публичный descriptor клиента: `assets/support_report/recipient.json`:

```json
{"version":1,"keyId":"support-2026-01","publicKey":"<base64: 32 public bytes>"}
```

По явному выбору пользователя локальный CLI создал производственного получателя
`astoria-support-20261101-62ba1e85`. В `recipient.json` подключён только публичный
descriptor, не демонстрационный ключ. Приватный DPAPI-файл находится вне проекта:
`%LOCALAPPDATA%\AstoriaSupport\keys\astoria-support-20261101-62ba1e85.dpapi`.
Приватные байты не читались моделью и не выводились. Текущие Windows/APK release
сборки уже пересобраны с этим публичным получателем. Приватная часть никогда не
нужна приложению, Git или репорту.

Null-получатель остаётся безопасным состоянием для неподключённой сборки: тогда
предпросмотр работает, но экспорт выключен до доверенного public descriptor.

## Локальный CLI для оператора — Windows

CLI работает с DPAPI CurrentUser и проверяет ACL/обычный файл на том же открытом
handle. Приватная часть хранится только в DPAPI-защищённом файле; значения ключа
не передаются через argv/env/stdout/stderr. Аргумент `--private` — **путь**, не ключ.
Существующие файлы генератор не перезаписывает. Hard links, reparse points и
расширенный доступ к приватному файлу отвергаются. Другие платформы для этой
защищённой CLI-custody пока не поддерживаются.

Нужен весь каталог `build/support-report-cli/bundle`, включая native libraries,
а не один EXE. Собрать его можно установленным Dart 3.12:

```powershell
dart build cli --target bin/support_report_cli.dart --output build/support-report-cli
```

`dart run tool/support_report_cli.dart ...` также учитывает native hooks, но SDK
может печатать собственные build-логи. Для отдельного готового инструмента используй
bundle. Обычный `dart tool/support_report_cli.dart` не является поддерживаемым
способом загрузки native assets.

### Первичная генерация — выполнить доверенному оператору локально

Первичная генерация уже выполнена с явного согласия пользователя через готовый
CLI, без чтения приватных байтов. Пример ниже — для нового получателя или ротации,
не команда повторного создания существующей пары. Выбери локальную папку вне
репозитория, не облачный или общий каталог. Например, из корня проекта:

```powershell
$root = Join-Path $env:LOCALAPPDATA 'AstoriaSupport'
New-Item -ItemType Directory -Force -Path "$root\keys", "$root\public" | Out-Null
$cli = (Resolve-Path 'build/support-report-cli/bundle/bin/support_report_cli.exe').Path
& $cli keygen --private "$root\keys\support-2026-01.dpapi" --public "$root\public\support-2026-01.json" --key-id support-2026-01
```

CLI выдаёт только фиксированное подтверждение. Не открывай/не присылай приватный
файл модели. Сохрани его с исходным Windows-профилем/машиной; одного копирования
DPAPI-файла на другую машину недостаточно для гарантированного восстановления.
Потеря приватной custody означает невозможность расшифровать соответствующие
репорты. При ротации сохрани старые пары и сопоставление `keyId`.

В приложение копируется **только публичный** JSON:

```powershell
Copy-Item "$root\public\support-2026-01.json" 'assets/support_report/recipient.json'
flutter build windows --release --no-pub
flutter build apk --release --no-pub
```

Для Windows→Android native hooks могут потребовать Git Bash и GNU make в PATH
этого процесса. Не заменяй их WSL-launcher и не меняй системный PATH ради примера.

### Чтение полученного репорта

```powershell
& $cli decode --private "$root\keys\support-2026-01.dpapi" --public "$root\public\support-2026-01.json" --input 'C:\Reports\astoria-support-report.astreport'
```

После полной аутентификации CLI выводит точный JSON. Он может содержать разрешённые
пользователем личные фрагменты: не публикуй его целиком и не перенаправляй вывод
в общие логи. Отказ имеет exit code 2 и конечную категорию ошибки; повреждённый
пакет не выдаёт частично расшифрованный текст. Decoder не исполняет команды,
скрипты, пути или инструкции из репорта.

## Границы проверки

Готовые локальные артефакты:

- `build/app/outputs/flutter-apk/app-release.apk` — 156.9 MB, публичный получатель подключён.
- `build/windows/x64/runner/Release/Astoria.exe` — нужен весь каталог `Release`.
- `build/support-report-cli/bundle/bin/support_report_cli.exe` — нужен весь `bundle`.

Контролируемые native/AEAD/DPAPI/ROOT и UI-тесты используют синтетические БД/ключи,
не настоящие данные пользователя. Они не заменяют запуск на физическом Android,
проверку каждого SAF-провайдера, live-model диагностику или гарантию hard deadline
при зависшем дисковом I/O. Текущие результаты и остальные задачи:
[ASTORIA_ASSISTANT_STATUS.md](ASTORIA_ASSISTANT_STATUS.md).
